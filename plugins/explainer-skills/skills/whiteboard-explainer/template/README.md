# Whiteboard explainer: project template

A starting point for a hand-drawn whiteboard explainer video made with
[fframes](https://fframes.studio) 1.3 (Rust) and a local text-to-speech voice. Everything on the board is
drawn, written, circled and underlined **on the word that names it**: the narration build writes every
spoken word's time into `src/cues.rs`, and scenes start a drawing with `c.w(beat, "word")`.

The template is a complete ~1.5-minute demo ("binary search, in about a minute"): a cold open with a title,
a slide that builds up on the spoken words, an annotated figure card with a camera push-in, a multiple-choice
quiz with a countdown, and an outro. Copy it, check that it builds and renders, then replace the demo with
your own video.

## What's in it

```
Cargo.toml, Cargo.lock   fframes =1.3.0 (features: compile-time-svgtree, cli, 3d, wgpu), fast release rebuilds
env.sh                   build environment (FFMPEG_DIR, LIBCLANG_PATH) for bash; `source env.sh`
src/main.rs              loads media/ (compiled in), audio/, sprites/, figs/ (at run time); CPU frame renderer
src/lib.rs               scene dispatch, chapter chips (0.1 s black dip), image table, SceneCues c.w/c.wn/c.we
src/kit.rs               the drawing kit: hand-drawn strokes, handwriting, camera, paper Card, widgets, icons
src/objs.rs              reusable objects (mcq quiz board, cells, code/chat/quote cards, plots) + the video's own
src/duck.rs              the host sprite: where it stands per scene, talking bob from the voice
src/t3d.rs               optional 3D blocks (fframes three_d); unused by the demo
src/s_*.rs               the demo scenes: s_intro (Hook, Outro), s_idea, s_figure, s_quiz
src/cues.rs              GENERATED by narration/build_vo.py (or est_cues.py): scene/beat/word times
src/envelope.rs          GENERATED by narration/envelope.py: voice loudness per frame
src/figs.rs              GENERATED by tools/prep_figs.py: figure names and pixel sizes
src/metrics.rs           GENERATED by tools/font_metrics.py: Excalifont advance widths
narration/script.py      the narration: scenes -> beats (one sentence each), PAUSE for quizzes
narration/tts.py         voice settings; finds the local-tts skill's say.py; ffmpeg and Whisper helpers
narration/build_vo.py    voice + cache + tempo + pause shaping + word alignment -> audio/, cues.rs, envelope.rs
narration/est_cues.py    provisional cues + silent track, no TTS needed (draw scenes before the voice exists)
narration/words.py       checks every c.w(..) key and every scene's dispatch arm; writes narration/WORDS.md
narration/audit_vo.py    unprompted Whisper transcript of every clip, diffed against the script
narration/tts_try.py     voice a few spelling variants and print what Whisper hears
narration/make_srt.py    subtitles (.srt) with a voice-spelling -> display map
narration/envelope.py    voice loudness per frame (run by build_vo.py and est_cues.py)
narration/glitch.py      finds frames that change and snap back in the encoded mp4 (render glitches)
tools/make_demo_fig.py   draws the demo's figure (figs/guesses.png)
tools/prep_figs.py       writes src/figs.rs from figs/*.png
tools/font_metrics.py    writes src/metrics.rs from the handwriting font
tools/get_pet.py         downloads and slices a Codex pet into sprites/ (the host)
tools/lowprio.py         runs a command at idle CPU priority
media/                   fonts (Excalifont, Inter, JetBrains Mono; SIL OFL, texts in media/licenses/)
figs/guesses.png         the demo figure
sprites/                 empty: the host's frames go here (tools/get_pet.py)
HELPERS.md               the brief for parallel scene helpers (fill in the <...> parts per video)
STORYBOARD.md            the demo's storyboard, as an example of the level of detail helpers need
THIRD_PARTY.md           licences of everything shipped, downloaded or linked
```

## Requirements

- **Rust** 1.85 or newer (edition 2024): `rustup update`.
- **FFmpeg shared libraries** and **libclang**, for fframes. See the comments in `env.sh` for Windows, macOS and
  Linux. Set `FFMPEG_DIR` and `LIBCLANG_PATH` in your shell profile (or edit the defaults in `env.sh`), then
  `source env.sh` before cargo and before running the built binary.
- **Python 3.10+** with `pip install numpy soundfile librosa faster-whisper pillow` (`fonttools` too if you
  change the handwriting font). On Windows with an NVIDIA GPU, faster-whisper runs on CUDA when PyTorch with
  CUDA is installed in the same environment (it loads the cuBLAS/cuDNN DLLs); otherwise it uses the CPU.
- **The `local-tts` skill** for the voice (it installs and configures the local Qwen3-TTS engine). The voice
  scripts find its `say.py` through `LOCAL_TTS_SAY`, then `~/.claude/skills/local-tts/scripts/say.py`, then a
  plugin install under `~/.claude/plugins/`. Without it, use `narration/est_cues.py` (silent draft).

## Start a new video from the template

```bash
cp -r <path to this template> my-video/video       # or: copy the folder in your file manager
cd my-video/video
source env.sh                                      # FFMPEG_DIR / LIBCLANG_PATH from your environment
cargo build --release                              # first build ~5 min (fframes and its dependencies)
```

Keep research notes, the paper and raw figures next to it (`my-video/research/`), not inside `video/`.

### 1. Voice (or a silent draft)

```bash
python -I narration/build_vo.py     # TTS for every line (cached), word timings -> audio/narration.wav, src/cues.rs
python -I narration/words.py        # must print "0 bad word cues"
```

No voice yet (no TTS installed, or the GPU busy)? `python -I narration/est_cues.py` writes estimated timings and
a silent `audio/narration.wav`; the scenes re-time themselves when `build_vo.py` runs later. If another app is
using the GPU, `GGML_BACKEND=CPU` moves the TTS to the CPU (about 4x slower) and `WHISPER_DEVICE=cpu` moves the
alignment; wrap long jobs in `python -I tools/lowprio.py ...`.

Then audit what a listener hears: `python -I narration/audit_vo.py` prints every line whose unprompted
transcript differs from the script. Fix real misreadings by respelling the line in `script.py` (test variants
with `python -I narration/tts_try.py variants.txt`), and build the voice again (only changed lines are voiced).

### 2. Look at it

The binary has to run from the project folder (it reads `audio/`, `figs/`, `sprites/` from there).

```bash
R timeline                          # scenes and durations (R = cargo run --release -q --, from env.sh)
R inspect                           # missing images or glyphs, text off the canvas, invalid SVG
R strip Idea -n 12 -o check/idea_strip.png
R frame "Idea@end" "Figure@50%" -o check
R frame "Idea@end" --crop 900,300,700,500 -o check     # zoomed crop for small labels
R preview 30s                       # real-time window with sound
```

Expect a few warnings for text crossing the canvas edge in the Figure scene while the camera moves: those are
frames mid-zoom.

### 3. A host (optional)

```bash
python -I tools/get_pet.py --list
python -I tools/get_pet.py rubber-duck-2-0       # slices it into sprites/; check the pet's rights before publishing
```

`src/duck.rs` places the host per scene (big in the cold open, the quizzes and the outro; small bottom-right
otherwise). With `sprites/` empty no host is drawn and everything else renders.

### 4. Render and check

```bash
timeout 1200 ./target/release/explainer render -o out/video.mp4     # explainer.exe on Windows
python -I narration/glitch.py out/video.mp4                          # flags frames that change and snap back
python -I narration/make_srt.py out/video.srt                        # subtitles next to the mp4
```

The CPU frame renderer is the default on purpose: the GPU video path has pasted streaks and bands of other
frames into long renders. x264 encodes on the CPU too. `glitch.py` runs on the encoded file; the host's blinks
and rolling counters cause a few harmless events, so look at the flagged frames before deciding.

## Replacing the demo with your video

1. `narration/script.py`: your scenes and beats (~150 wpm, one sentence per beat, spelled for the voice,
   `PAUSE` in each quiz). Keep the demo quiz's beat layout for `mcq` (0 "Quiz N.", 1 question, 2-5 options,
   6 PAUSE, 7 "The answer is X.", 8 why it's right, 9 why the trap is wrong).
2. `figs/`: your figures as PNGs, then `python -I tools/prep_figs.py`. Delete `figs/guesses.png` and
   `tools/make_demo_fig.py`.
3. `src/objs.rs`: replace the "this video" section with your recurring objects and colour meanings.
4. `src/s_*.rs`: your scene functions (`pub fn name<'a>(t: f32, c: &SceneCues) -> Svgr<'a>`); add their `mod`
   lines, the dispatch arms and the chapter chips in `src/lib.rs`; update the scene names in `src/duck.rs`
   `spot`. A scene without an arm renders as a placeholder with its narration, which is handy while drawing.
5. `STORYBOARD.md` and `HELPERS.md` for your video, if you fan scenes out to helpers.
6. Build the voice, run `words.py`, check, render, as above.

## Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `FFMPEG_DIR`, `LIBCLANG_PATH` | env.sh, cargo | FFmpeg shared build and libclang for fframes |
| `LOCAL_TTS_SAY` | narration/tts.py | path to the local-tts skill's `say.py` |
| `GGML_BACKEND=CPU` | say.py (the TTS engine) | TTS on the CPU when the GPU is busy |
| `FFMPEG` | narration scripts | the ffmpeg executable (else `$FFMPEG_DIR/bin/ffmpeg`, else PATH) |
| `WHISPER_DEVICE` (`auto`/`cuda`/`cpu`), `WHISPER_THREADS`, `WHISPER_COMPUTE` | build_vo, audit_vo, tts_try | where Whisper runs |
| `AUDIT_SCENES=Hook,Idea` | audit_vo.py | audit only some scenes |
| `FF_3D=cpu` | src/t3d.rs | 3D insets on the CPU |
| `RAYON_NUM_THREADS`, `CARGO_TARGET_DIR` | fframes, cargo | fewer render threads; a shared build folder |
